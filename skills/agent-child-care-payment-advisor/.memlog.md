- (decision) Build CarePay Advisor (agent-child-care-payment-advisor) as a stateless, on-demand, release-controlled, read-only advisor for authenticated child care providers. Version one includes payment-risk snapshot, upcoming payout, weekly forecast, recovery actions, what-if analysis, and data-quality checks. MCP/API calls retrieve authorized live data and resolve filters; deterministic Python performs all financial, deadline, absence-limit, and risk calculations. County rate-plan rules come from API data; state documentation is transformed into versioned, testable rule data rather than interpreted by the LLM per request. The agent never changes operational records.
- (direction) V1 is Colorado-only. Authoritative documents are State Docs/8 CCR 1403-1.pdf and State Docs/CCCAP Provider Handbook English.pdf. One authenticated provider login maps to one facility; snapshot aggregates that facility and drills into county and child. Existing endpoint inventory: getAuthData, getCountyData, getHolidayList, getProviderData, getSchedules, getServicePeriods. Baseline acceptance example: Denver toddler, October 1-31, 22 authorized days, 18 attended, 4 absences with cap 3, 21 reimbursable days, county daily rate less copay = net, expected payout ,260; confirmation by November 5; EFT 10-14 business days, expected November 15-20. Risks include missing parent validation and excess absences.
- (decision) User approved the CarePay Advisor persona and capability draft with attendance risks explicitly evaluated and prioritized first because they directly affect ongoing and upcoming payments. Use a hybrid relationship model: MCP/server enforces session-derived provider isolation and coherent authorized datasets; bundled Python resolves calculation-specific joins, validates inputs, and performs all calculations. State-rule data changes require business and compliance owner approval, effective dates, provenance, and tests. Greeting/facility identity comes from getProviderData. Initial delivery is VS Code GitHub Copilot Chat, with Salesforce embedded chat as the intended production surface.
- (decision) Parent confirmation policy: before the deadline, include affected service only as conditional forecast and mark the full affected amount at risk; after the deadline, exclude it from expected payout and classify it as disputed. Declined customize override hooks; emit metadata only and keep behavior release-controlled. Prepare baseline-quality and trigger-accuracy evaluations.

Baseline and trigger eval cases staged successfully, but runtime executions were skipped because no non-interactive VS Code Copilot eval adapter is configured. Production remains blocked on complete API response mappings, governed rule extraction/citations, and payment-calendar semantics documented in references/setup-guide.md.
